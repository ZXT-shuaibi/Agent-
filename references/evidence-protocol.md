# 证据协议

## 来源标签

- '[用户事实]'：用户明确做过、能说明时间/角色/过程的工作。
- '[源码证据]'：本地拉取仓库中可定位的文件、行号、符号、测试或配置。
- '[公开资料]'：公司、岗位、项目的公开页面；记录 URL、访问日期和可信度。
- '[建议改造]'：为达到目标链路建议实施的工作。
- '[不可写成已完成]'：当前没有完成或证据不足，不能写成成果。

## 证据最小集

最终推荐的仓库必须：

1. 由拉取脚本成功克隆，manifest 状态为 cloned。
2. 至少有 5 个本地源码证据点，至少覆盖链路中的 3 段（入口、处理/状态、Tool/RAG/副作用、评测/观测中的任意三段）。
3. 每个证据点含 path、line、symbol、kind、excerpt 和 confidence。
4. README、搜索摘要和模型记忆只能用于定位候选，不能单独证明“已有能力”或“本人负责”。

## 事实账本

推荐报告按以下四栏输出，不得合并：

| 栏位 | 允许内容 | 禁止内容 |
|---|---|---|
| 已有能力 | 本地源码或用户事实可证明的能力 | 推断的架构、未读源码的 README 宣传 |
| 建议改造 | 为业务场景设计的增量工作 | 写成已上线或已完成 |
| 完成后可写 | 完成改造并补齐证据后的候选表述 | 现在直接放进实习 bullet |
| 当前不可写 | 证据不足、角色不明、指标无来源 | 用“参与/负责”模糊掩盖缺口 |

指标必须记录来源。没有监控或实验数据时使用“待测量/估算”，不得伪造百分比。
