# 经历承载项目与高价值业务背景

## 先定义关系

“经历承载项目”是一个业务背景更适合简历的外部项目。曼弗实习提供真实的技术问题、链路和设计启发；外部项目提供可公开验证的业务载体。不能把外部项目说成曼弗的生产系统，也不能把没有在外部项目中实现的设计点写成已完成。

正确关系是：

```text
曼弗实习事实 → 抽象高价值链路 → 选择业务承载项目 → 在承载项目中重实现/改造 → 形成独立项目表达
```

## 承载项目最低条件

一个项目只有同时具备以下大部分条件，才适合承载实习链路：

1. 有明确业务对象，例如合同、供应商、事件、指标、变更、文档或审计案件，而不是只有聊天消息。
2. 有生命周期，例如提交、处理、复核、审批、驳回、重试、交付、归档或回滚。
3. 有可调用的系统边界，例如数据库、搜索、文件、工单、CI、数据目录或第三方 API。
4. 有证据和责任边界，例如引用、审计日志、审批记录、版本、权限或人工接管。
5. 有可验证的业务结果，例如处理时延、人工复核量、引用正确率、Tool 成功率、任务恢复率或成本。
6. 有清晰的二次开发入口，能把链路放入状态层、Tool 层、评测层或数据层，而不是只能改 prompt。

## 优先背景

| 业务背景 | 最适合承载的链路 | 为什么比普通聊天项目更有含金量 | 可落地的改造面 |
|---|---|---|---|
| 合规证据链与整改闭环 | 长程编排、RAG 引用、权限、人工审批、审计 | 有证据责任、审批状态和整改结果，能追问事实来源 | 案件状态机、证据 Tool、引用校验、审批节点、审计轨迹 |
| 合同义务与供应商履约协同 | 文档抽取、长期记忆、提醒任务、Tool 幂等、人工复核 | 业务对象和时间约束清晰，结果不是一句生成文本 | 合同条款模型、履约任务、提醒队列、版本记忆、异常补偿 |
| 企业指标口径治理与问数审计 | SQL Tool 安全、权限、评测、成本/延迟、可追溯 | 能证明答案、SQL、口径和权限，避免“问数聊天”空泛 | 指标目录、查询审批、SQL 校验、结果评测、血缘记录 |
| 研发变更风险门禁与发布复盘 | 多 Agent 协作、Tool 调用、长任务、审批、回滚 | 连接代码、工单、CI 和发布结果，有明确风险闭环 | 变更状态、影响分析 Tool、人工放行、失败恢复、复盘评测 |
| 知识变更影响分析与内容发布 | 增量 RAG、版本、租户权限、引用评测、人工发布 | 关注知识生命周期和错误传播，不是静态知识库问答 | ingestion、版本索引、权限过滤、引用检查、发布回滚 |
| 跨系统异常处置与运营值班 | Tool 可靠性、重试退避、幂等、人工接管、观测 | 需要处理真实副作用和失败边界，工程追问密度高 | 事件分级、处置 DAG、Tool 策略、补偿任务、trace 和告警 |
| 采购寻源与供应商准入 | 多 Agent 分工、检索、规则、审批、记忆 | 角色边界和决策依据清晰，适合讲协同与审计 | 供应商档案、材料核验、评分规则、审批流、证据留存 |

这些背景不是曼弗科技公开业务事实，只是候选承载方向。最终必须根据用户能公开说明的真实实习链路和目标项目源码确认。

## 高饱和背景降权

以下项目不是绝对淘汰，但如果没有额外闭环，默认不作为首选：

- 通用 AI 客服聊天、企业知识问答、AI 写作、会议纪要；
- 单次报告生成、简单投研 Demo、简历筛选和网页搜索助手；
- 只有 prompt、向量库或一个函数 Tool 的薄封装；
- 没有业务对象、状态、权限、失败处理、评测或用户交付的 UI 项目。

若采用这些背景，必须补齐至少两项高价值闭环，例如“知识版本 + 权限过滤”“任务恢复 + 人工审批”“轨迹评测 + 线上回归”，否则不能把它作为高含金量承载项目。

## 评分模型

对外部项目按 0–5 分打分，业务相似度不是主指标：

| 维度 | 判断问题 | 权重 |
|---|---|---:|
| 业务承载自然度 | 链路放入业务对象和生命周期后是否顺畅 | 30% |
| 链路嵌入点 | 是否有状态、Tool、数据、评测或观测的真实代码入口 | 25% |
| 源码证据密度 | 是否能拉取并找到至少 5 个跨层证据点 | 20% |
| 业务独特性 | 是否避开同质化，同时能说明用户和结果 | 15% |
| 可实现范围 | 学生能否在目标时间内完成最小重实现 | 10% |

star 只能作为弱社区信号，不能抵消业务承载自然度或源码证据不足。

## 链路承载映射

每个候选必须填写以下字段：

| 字段 | 填写要求 |
|---|---|
| `internship_chain` | 曼弗实习中真实接触的链路，标 `[用户事实]` 或 `[待确认]` |
| `carrier_scenario` | 外部项目的业务背景，不写成曼弗内部事实 |
| `business_object` | 目标项目处理的合同、事件、指标等对象 |
| `lifecycle` | 对象状态流转和终态 |
| `chain_insertion_point` | 链路放入的本地模块、类、任务、Tool 或测试 |
| `minimal_reimplementation` | 用户必须实际完成的最小代码和验证 |
| `claim_level` | 独立项目、建议改造、或当前不可写 |

只有完成外部项目中的重实现并补齐测试、日志或评测证据后，才能把对应内容写成项目成果；否则只能写成建议改造。
