# Agent 岗位画像

## 入口与主流程

Agent 项目的入口通常是 API/CLI/worker、graph/orchestrator、Tool 注册表、prompt/flow 配置或 RAG ingestion；主流程通常为：

```text
用户任务 → 意图/任务分解 → 状态/编排 → 模型决策 → Tool/RAG → 持久化副作用 → 评测/观测 → 用户交付
```

## 高价值术语

| 大白话 | 工程表达 |
|---|---|
| 多个 prompt 串起来 | 状态化任务编排 / workflow graph |
| 模型失败再试一次 | 带退避和幂等约束的重试策略 |
| 给模型一个函数 | 具备 schema、权限和审计的 Tool contract |
| 让任务跑很久 | 持久化 checkpoint 与可恢复执行 |
| 存聊天记录 | 短期状态与长期记忆生命周期 |
| 查知识库回答 | 具备权限过滤和引用评测的 RAG |
| 测模型准不准 | 轨迹级评测与回归数据集 |
| 看日志排问题 | Agent trace、成本/延迟和失败分类 |
| 几个 Agent 协作 | 角色边界、共享状态和人工接管 |

## 高频追问

任务状态如何持久化？中断后如何续跑？Tool 产生副作用时如何防重复？失败重试是否有退避和上限？评测数据如何构建、如何防止泄漏？记忆何时写入和删除？如何处理提示词注入与权限？token 成本和延迟如何治理？个人在团队决策中的边界是什么？
