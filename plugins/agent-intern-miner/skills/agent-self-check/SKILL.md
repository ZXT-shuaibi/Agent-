# Agent 质量门禁

> 内部 ID：`agent-self-check`

## 作用

在投递或交付前做最后一次质量门禁：检查证据是否足够、角色是否真实、Agent 工程深度是否成立、指标能否追溯、表达能否在 30 秒和 2 分钟内讲清。

## 输入

- 完整项目/实习包装报告；
- 简历 bullet、证据清单和数据来源；
- 拷打报告（如果已经执行）；
- 目标岗位要求，可选。

## 输出

通过/警告/高危表格，必须修改项、建议补证据项、当前可写内容和下一步。检查不完整时明确指出缺少的前置材料。

## 何时使用

准备把 Agent 项目写进简历、投递或对外展示前使用。它只检查现有材料，不会新增未证实事实。

## 怎么用

说：“使用 `agent-self-check` 检查这份 Agent 包装，重点看证据、个人角色、Tool 稳定性和评测指标。”出现 🔴 时，回到 Agent 项目/实习包装或 Agent 面试拷打修复。

只检查已有报告和包装，不新增未证实事实。若缺少前置材料，明确标记检查范围不完整。

## 必检项目

### 证据与真实性

- 是否至少有五个本地源码证据点，并覆盖入口、编排/状态、Tool/RAG/副作用、评测/观测中的至少三段？
- 每条 bullet 是否有 [源码证据]、[用户事实] 或 [公开资料] 来源？
- [建议改造] 和 [不可写成已完成] 是否与已完成成果分栏？
- 是否把开源项目或通用方案写成曼弗科技实习？若是，标 🔴。
- 角色真实性：个人角色是否清楚，是否误用了“从 0 到 1 负责整个系统”？

### Agent 工程深度

- 是否能解释 checkpoint、恢复/取消、超时、重试、退避、幂等和补偿？
- Tool 是否有 schema、权限、审计、提示词注入防护、沙箱和副作用边界？
- 是否有评测数据集、trajectory、指标来源、回归和线上反馈？
- 记忆是否说明写入、检索、摘要、衰减、隔离和删除？
- 是否有 trace、成本/延迟、模型路由、降级和预算治理？

### 表达与面试

- 能否用 30 秒讲清背景、方案和结果？
- 能否用 2 分钟展开 A → B → C、个人角色和取舍？
- 每条 bullet 是否埋了真实可回答的面试钩子，而不是热门名词？
- 指标是否来自监控、实验、日志或明确的估算？
- 主文是否只讲业务链路、关键机制、失败边界和证据 ID，而把路径、行号、符号和代码摘录放到证据附录？
- 是否用大量类名或代码堆叠代替了对设计价值和取舍的解释？若是，标警告并按 [证据优先与精简讲解](../../references/evidence-first-explanation.md) 重写。

## 输出

生成通过/警告/高危表格，列出必须修改、建议补证据、当前可写和下一步。任何 🔴 高危项都必须回到 agent-package 或 agent-grill 修复后再检查。
