# Agent 面试拷打

> 内部 ID：`agent-grill`

## 作用

模拟压力型面试官，逐条验证 Agent 项目的业务必要性、状态恢复、Tool 副作用、安全、评测、记忆、成本和个人角色，找出会被追问击穿的地方。

## 输入

- 已写的简历 bullet；
- 项目链路报告和证据 ID；
- 你声称的指标、技术选型和个人职责；
- 可选的目标岗位或面试官风格。

## 输出

每个问题标记 🔴/🟡/✅，输出漏洞清单、原 bullet、修补问题、需要补的证据和下一轮追问。高危问题清零前不生成逐字稿。

## 何时使用

简历已经写好但担心“只会说框架名”、指标没有来源、无法解释失败处理或角色边界时使用。它不负责替你补写不存在的事实。

## 怎么用

说：“使用 `agent-grill`，按 Python Agent 后端面试拷打这 3 条 bullet，一次只问一个问题。”你回答后再进入下一层追问。

一次只问一个问题，等待用户回答后再深入。目标是找出面试官能击穿的点，不替用户编答案。每个问题标记 🔴 高危、🟡 中危或 ✅ 可防守。

## 追问顺序

1. **业务闭环**：用户任务是什么？为什么需要 Agent，而不是规则/普通 API？
2. **编排与长程状态**：任务如何分解？状态 schema 和 checkpoint 存在哪里？中断后如何恢复、取消和续跑？
3. **失败与副作用**：Tool 超时/返回脏数据/重复执行怎么办？重试是否有退避、上限、幂等键和补偿？
4. **安全**：谁能调用 Tool？如何做 schema 校验、权限、提示词注入防护、沙箱、审计和人工确认？
5. **评测**：数据集怎么来？如何记录 trajectory？任务成功率、Tool 成功率、事实性、引用、成本和延迟如何计算？如何防评测泄漏？
6. **记忆**：什么写入短期/长期记忆？何时摘要、衰减、隔离和删除？如何避免错误记忆污染？
7. **观测与成本**：trace 如何关联一次任务？如何定位瓶颈、模型路由、降级和预算超限？
8. **角色真实性**：哪些是你亲自实现和验证的？哪些是 mentor 设计或同事负责？证据文件和时间是什么？

## 判定

- 🔴：无证据却声称已完成、无法解释状态丢失/副作用重复、指标无来源、把开源建议改造写成实习成果。
- 🟡：能讲主流程但缺少边界、评测、观测或协作细节。
- ✅：能给出证据、取舍、失败策略、数据来源和个人范围。

输出漏洞清单、原 bullet、修补问题、需要补的证据和下一轮问题。高危未清零时不要生成逐字稿。
